# Security and privacy

Vault is a personal, self-hosted application for one trusted household or operator. Profiles organize an archive; they are not separate authorization boundaries. Anyone with the vault password can read all connected profiles.

Default listeners and Compose ports are loopback-only. Before the first setup, a vault that is reachable beyond loopback requires a one-time setup code. This covers a non-loopback bind address (including Docker) and a non-local base URL. The code is printed only to the server log. Concurrent setup requests have exactly one winner. For remote access, use an authenticated private network such as Tailscale with HTTPS. Do not forward the HTTP port directly to the internet. Use a reverse proxy only with an exact `VAULT_BASE_URL`; proxy-supplied host headers must match it. See [installation](docs/INSTALL.md).

The local password is salted and scrypt-hashed. Changing it requires the current password and signs out other sessions. Password checks back off per client address and across the vault, capped at one minute, so a shared proxy address cannot lock the owner out for long. `X-Forwarded-For` is ignored unless `--trust-proxy` names the proxy's address. Browser sessions are HttpOnly and SameSite=Strict, and expire on server restart. An OAuth callback is accepted only while the session that started it is still valid. Mutating requests require a non-simple same-origin header; cross-origin writes and unexpected Host headers are rejected. With a local base URL, only the `localhost`, `127.0.0.1` and `[::1]` aliases on the configured port and scheme are accepted. OAuth states are random, expiring and one-use. Tumblr scopes are checked on authorization and refresh. Tokens and application secrets are stored in a private local config file so unattended backups can refresh access. If Tumblr rotates a refresh token but grants anything other than `basic offline_access`, Vault keeps the rotated refresh token so the account can recover. It discards the refused access token and never uses it. Release workflow actions are pinned to full commit SHAs. Encryption of the disk and backups is the operator’s responsibility. On Windows, protect the data directory using the user’s filesystem ACLs.

Original downloads accept only HTTPS Tumblr hosts, including every redirect. External embeds are retained as source metadata but are not fetched. User post content is rendered as text, never inserted as HTML. Model files download from Hugging Face only when local image indexing/search is enabled and used.

If you find a vulnerability, use the repository’s private vulnerability reporting if available. Otherwise open an issue asking for a private contact without including exploit details or credentials. Never attach a personal database or raw account export.
